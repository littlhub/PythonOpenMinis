# Wiki Distill — 从对话记忆提取知识库

知识库 = `knowledge/<分类>/<主题>.md` 下的长文档（每个文件是一块可检索的
RAG 语料）。**知识库与记忆是两套东西**：记忆（`memory/`）是"关于我和这段关系"，
按 daily/long-term/rules/troubleshooting/preferences 五类；知识是"可复用的资料"，
按下面五类归档：

| 分类 | 目录 | 装什么 |
|------|------|--------|
| 概念 | `knowledge/概念/` | 方法、原理、风格、术语 |
| 实体 | `knowledge/实体/` | 具体的人/项目/工具/作品 |
| 来源 | `knowledge/来源/` | 文章、文档、链接、论文、数据集 |
| 分析 | `knowledge/分析/` | 分析报告、结论、复盘、决策记录 |
| 模板 | `knowledge/模板/` | 可复用的模板、骨架、清单、提示词 |

`knowledge/index.md` 由系统按分类自动重建（不要手写）；「知识」页的**图谱**
视图就是靠文档之间的 `[[双链]]` 连线的。

## 与其它记忆技能的分工

- `memory-capture`：单条偏好/约定**当场**写（daily/rules）——顺手、即时；
- 本技能：把一段对话/几天的记忆**蒸馏成体系化主题文档**——低频、重整理；
- 只有本技能产出**知识**；记忆与知识分开写，不要混。

## 触发时机

- 用户说：整理记忆 / 生成 wiki / 建知识库 / 把刚才整理成笔记 / 沉淀结论；
- 多轮分析、决策、排障结束，结论值得跨会话复用；
- 每日日志积累（或压缩后记忆已写入），适合阶段性归纳时。

## 流程

1. **检索现状（最多 2 次 memory_get）**：第一次直接
   `memory_get(scope=all)` 且 **keywords 留空**（一次性拿全量记忆），
   不要再换关键词逐条搜索；想确认某个具体主题时，才允许第 2 次带关键词的
   定位检索（查知识库用 `scope=knowledge`）。
2. **蒸馏**：把相关对话要点、决策与原因、可复用方法提炼为结构化 Markdown
   （中文要点式；只留跨会话成立的内容）。
3. **写入（本任务的完成动作，必须执行）**：`memory_write`：
   - `scope=wiki`、`topic=<主题名>`、`category=<概念|实体|来源|分析|模板>`、
     `content=<正文>`
   - 同一主题继续追加（追加带时间戳段落），新主题自动建文件
4. **建立双链**：正文里提到别的主题时写成 `[[主题名]]`，知识页图谱才会连线。
5. **收尾**：任务完成的标志是**至少一次成功的 `memory_write(scope=wiki)`**；
   `knowledge/index.md` 会自动重建，写完即向用户总结已沉淀的主题与文件，
   不要再继续检索。

## 检索纪律（防止空转，务必遵守）

- 单个"整理"任务里 `memory_get` **最多调用 2 次**：第 1 次全量、第 2 次可选定位。
- 若全量检索后仍觉得素材不足：**停下来**，直接基于已获得的内容写文档，
  或向用户说明"当前记忆里没有足够材料，需要我先记下一些内容再整理"。
- 绝对禁止反复换关键词重试 `memory_get`——这不会带来新信息，属于空转。
- 素材足够就写，写完全量内容前不要做无谓的多次小规模检索。

## 规范

- 一个主题一个文件：`图像分析规范`、`生图配置`、`银杏路上的约定`…
- 分类要选对：越"通用可复用"越靠概念/模板，越"具体的一次对象"越靠实体/分析。
- 保留决策与原因；不写密钥、一次性细节。
